# Historical records

These files preserve rationale and the original limits of past observations.
They are not the current task list, development setup, deployment instructions
or permission to execute old plans. Start with [current tasks](../TASKS.md),
[contributing](../../CONTRIBUTING.md) and the [acceptance plan](../ACCEPTANCE_PLAN.md).

- [Phase 2 gap analysis](PHASE2_GAP_ANALYSIS.md): original G-01–G-06 issue IDs.
- [Implementation assessment](IMPLEMENTATION_ASSESSMENT.md): pre-repair A-01–A-05 findings; do not treat them as present defects without checking source.
- [Deployment transaction design](DEPLOYMENT_TRANSACTION_DESIGN.md): original design and rationale for D-008.
- [Phase 3 execution notes](PHASE3_EXECUTION_2026-10-22_26.md): former rolling task log, including the WSL/native/VM evidence, matrix reconciliation and cloud TLS repair results.
- [Dated plans](plans/): 56 implementation/acceptance plans from 2026-10-22 through 2026-10-26. Completed checkboxes, old host paths and instructions to commit are historical context, not current authorization. Use the current harness and recheck prerequisites before any approved replay.

The one-time cloud migration handoff has been removed after source transfer and
checkout verification. Its useful development rules now live in CONTRIBUTING
and AGENTS; Git history retains the original handoff if migration history is
needed. Private VM images, keys, logs and source-transfer artifacts are not
part of this archive.

Keep new current results and blockers in TASKS. Archive only records whose
rationale or evidence boundaries are still useful; do not revive superseded
instructions, duplicate the current task list here or infer new test passes.
